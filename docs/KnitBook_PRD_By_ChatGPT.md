# KnitBook PRD
## 뜨개인을 위한 도안·작품·실 재고 관리 및 AI 기반 뜨개 플랫폼

- **문서 버전:** 1.0
- **작성일:** 2026-08-08
- **제품명:** KnitBook
- **제품 형태:** 모바일 반응형 웹 앱(PWA 확장 가능)
- **문서 목적:** MVP 개발부터 향후 AI 및 수익화 기능 확장까지 고려한 제품 요구사항 정의

---

# 1. 제품 개요

## 1.1 제품 소개

**KnitBook**은 뜨개질을 즐기는 사용자가 흩어져 있는 PDF 도안, 진행 중인 작품, 보유 실 정보를 한곳에서 관리하고, 향후 AI를 활용해 작품 선택부터 도안 분석·생성·뜨개 가이드까지 지원받을 수 있는 **개인 맞춤형 뜨개 관리 플랫폼**이다.

기존 뜨개 기록은 PDF 파일, 사진, 메모, 실 구매 내역 등이 여러 앱과 저장공간에 분산되는 문제가 있다.

KnitBook은 다음 세 가지 핵심 데이터를 연결하는 것을 핵심 가치로 한다.

> **도안 + 작품 + 실**

이 세 데이터를 지속적으로 축적하면 사용자의 뜨개 취향과 보유 재료를 이해하는 개인화 AI 서비스로 발전시킬 수 있다.

# 2. 문제 정의

## 2.1 사용자가 겪는 문제

### 도안 관리

- 구매하거나 다운로드한 PDF 도안이 휴대폰/PC에 흩어져 있음
- 어떤 도안을 가지고 있는지 기억하기 어려움
- 도안의 썸네일, 디자이너, 난이도 등을 찾기 어려움
- 실제 뜨개 중인 도안과 보관 중인 도안을 구분하기 어려움

### 작품 관리

- 여러 작품을 동시에 진행하면서 현재 진행 상황을 잊음
- 몇 단까지 떴는지 별도 메모가 필요함
- 사용한 실, 바늘, 사이즈 등의 정보를 다시 찾기 어려움
- 완성 작품을 체계적으로 기록하기 어려움

### 실 재고 관리

- 집에 어떤 실이 얼마나 있는지 파악하기 어려움
- 같은 실을 추가 구매할 때 기존 재고를 확인하기 어려움
- 브랜드/품번/LOT 번호를 기억하기 어려움
- 라벨이 사라진 실은 종류를 식별하기 어려움
- 남은 실을 활용할 작품을 찾기 어려움

### 정보 탐색

- "이 실로 무엇을 뜰까?"에 대한 답을 찾기 어려움
- 자신의 실 재고와 도안 조건을 연결하기 어려움
- 도안에 등장하는 뜨개 기법을 검색하고 배우는 과정이 번거로움

# 3. 제품 목표

## 3.1 핵심 목표

1. 개인의 뜨개 도안을 한곳에서 안전하게 관리한다.
2. 진행 중인 작품을 쉽게 기록하고 진척 상황을 확인할 수 있도록 한다.
3. 보유한 실을 디지털 재고로 관리한다.
4. **도안-작품-실 데이터를 서로 연결한다.**
5. 축적된 데이터를 기반으로 AI 개인화 기능을 제공한다.
6. 모바일에서도 뜨개 중 편리하게 사용할 수 있도록 한다.
7. 향후 유료 구독 및 커머스 등으로 확장 가능한 구조를 만든다.

## 3.2 핵심 가치 제안

> **"내가 가진 도안과 실을 알고, 지금 뜨고 있는 작품을 기억해주며, 다음 작품까지 추천해주는 나만의 뜨개 비서."**

# 4. 타깃 사용자

## 4.1 Primary Persona

### 취미 뜨개인

- 뜨개질을 꾸준히 즐기는 사용자
- PDF 도안을 여러 개 보유
- 동시에 여러 작품을 진행
- 실을 많이 구매하고 남은 실이 많음
- 모바일로 도안을 보면서 뜨는 경우가 많음

### Advanced Knitter

- 다양한 브랜드의 실을 사용
- 작품 기록을 중요하게 생각
- 여러 도안을 구매/보유
- 실과 도안의 조합을 고민
- AI를 이용한 도안 분석/추천에 관심이 높음

## 4.2 Secondary Persona

### 입문자

- 어떤 실과 도안을 선택해야 할지 모름
- 뜨개 용어와 기법에 익숙하지 않음
- 동영상 가이드가 필요함

### 콘텐츠 크리에이터 / 디자이너

향후 확장 대상

- 자체 도안을 판매하는 디자이너
- 뜨개 관련 콘텐츠 제작자
- 뜨개 클래스 운영자


```text

→ 라벨 촬영
```


# 8.7 실 라벨 OCR/AI 인식

사용자가 라벨을 촬영하면 다음 정보를 추출한다.

```text
브랜드
제품명
품번
색상명
색상번호
LOT
소재
중량
길이
권장 바늘
```

## 처리 방식

```text
사진 촬영
→ 이미지 전처리
→ OCR
→ 정보 추출
→ 구조화
→ 브랜드/제품 DB 검색
→ 후보 표시
→ 사용자 확인
```

## 중요 원칙

AI가 인식한 값을 바로 확정하지 않는다.

예:

```text
브랜드: Drops       [확신도 98%]
제품명: Alaska      [확신도 92%]
색상번호: 48        [확신도 81%]
LOT: 123456         [확신도 65%]

[수정] [저장]
```

# 8.8 라벨 없는 실 추론

라벨이 없는 실은 AI가 다음 정보를 추론하도록 한다.

### 이미지 기반

- 색상
- 밝기
- 질감
- 털 길이
- 꼬임
- 두께
- 형태

### 사용자 입력

- 실 굵기 선택
- 손으로 느끼는 촉감
- 사용했던 바늘 크기
- 무게
- 길이 추정
- 구입처/구매 시기

### 결과

```text
추정 소재:
울 60% / 아크릴 40% 가능성

추정 굵기:
DK ~ Worsted

추천 바늘:
4.0 ~ 5.0mm

유사 실:
A
B
C
```

단, **추론 결과를 사실로 표현하지 않고 "추정" 또는 "유사 후보"로 표시**한다.

# 9.1 AI 작품 추천

AI가:

3. 실 굵기 분석

5. 적합한 도안 검색
6. 예상 필요한 실 양 비교
7. 추천 결과 생성

예:

```text
추천 작품 1

- 난이도 ★★★
```

- 색상
- 실 종류

AI가 업로드된 도안과 현재 작품 진행 상황을 기반으로 답변한다.

예:

# 9.5 완성 작품 → 도안 생성

장기적인 핵심 AI 기능.

사용자가 완성 작품을 여러 각도에서 촬영한다.

```text
사진 업로드
↓
작품 유형 분석
↓
실/색상/굵기 분석
↓
뜨개 조직 분석
↓
구조 분석
↓
치수 입력/추정
↓
패턴 구조 생성
↓
도안 초안 생성
↓
사용자 검수
↓
PDF 도안 생성
```

## 생성 결과

- 작품 설명
- 필요한 실
- 게이지
- 사이즈
- 코수
- 단수
- 뜨개 기법
- 앞/뒤판 구성
- 소매
- 마감
- 차트
- 텍스트 패턴
- PDF

### 중요

초기 버전에서는 "완전 자동 도안 생성"보다:

> **AI가 분석 → 도안 초안 생성 → 사용자가 수정**

구조로 구현한다.

# 23. UX 원칙

## 23.1 뜨개 중에는 최소 조작

사용자는 양손을 사용하고 있을 가능성이 높다.

따라서:

- 큰 버튼
- 한 번 탭으로 기록
- 하단 고정 액션
- 자동 저장
- 마지막 위치 자동 복원

을 우선한다.

## 23.2 사진 중심

뜨개인은 텍스트보다 작품/실/도안 이미지를 빠르게 인식한다.

따라서:

- 작품 사진
- 실 사진
- 도안 표지

를 UI에서 적극 활용한다.

## 23.3 AI는 확정하지 않는다

특히 실 식별이나 도안 분석에서는 AI의 오류 가능성이 높다.

따라서:

```text
AI 추정
↓
사용자 확인
↓
저장
```

패턴을 기본으로 한다.

# 26. 장기 비전

KnitBook은 처음부터 모든 기능을 구현하기보다 다음 순서로 발전시키는 것을 권장한다.

```text

                 │   KnitBook    │
                 │  뜨개 데이터   │
                 └───────┬───────┘
                         │
          ┌──────────────┼──────────────┐

       도안 데이터      작품 데이터      실 데이터
          │              │              │

                         ↓

                         ↓
                    AI 추천/분석
                         ↓
```

이다.

# 28. MVP 개발 시 가장 중요한 설계 결정

## 28.1 데이터 연결을 처음부터 고려

MVP에서 AI를 구현하지 않더라도 아래 관계를 반드시 저장한다.

```text
User
 ├── Patterns
 │     └── Projects
 │            └── Yarns
 │
 └── Yarns
```

이 구조가 향후 추천 시스템의 기반이 된다.

## 28.2 PDF를 단순 파일로만 저장하지 않기

향후 AI 분석을 위해:

- PDF metadata
- page count
- extracted text
- detected techniques
- sizes
- yarn requirements
- gauge

를 저장할 수 있도록 확장성을 확보한다.

## 28.3 실 데이터를 최대한 구조화

단순히:

> "회색 실"

이라고 저장하지 않고,

```text
brand
product
material
weight
length
color
lot
thickness
needle
quantity
remaining_weight
```

처럼 구조화한다.

이 데이터가 향후 AI 추천의 핵심 자산이 된다.

# 32. 결론

KnitBook의 초기 핵심은 **"기록과 관리"**다.

하지만 제품 설계 단계부터 다음 단계의 AI 활용을 고려하여 데이터를 축적해야 한다.

특히 아래 세 가지를 핵심 데이터 모델로 삼는다.

> **Pattern — Project — Yarn**

이 세 데이터가 연결되면 KnitBook은 단순한 PDF 보관 앱을 넘어,

- 내가 가진 실로 무엇을 만들 수 있는지 알려주고
- 내가 어디까지 뜨고 있었는지 기억해주고
- 내가 좋아하는 작품을 추천하고
- 도안을 이해하기 쉽게 설명해주고
- 완성된 작품을 분석해 도안으로 만들어주는

**개인화된 AI 뜨개 플랫폼**으로 확장할 수 있다.

따라서 MVP에서는 기능을 과도하게 늘리기보다 **도안·작품·실 관리의 사용성을 완성도 높게 구현하고, 이 세 데이터를 정확하게 연결하는 것**을 최우선 목표로 한다.
